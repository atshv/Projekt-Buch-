# README schreiben

Ziel: In 30 Sekunden weiss der Leser, was das Projekt tut, ob es ihm hilft und wie er startet.

## Reihenfolge der Abschnitte (nur nehmen, was passt)
1. Titel + ein Satz: Was tut es, für wen.
2. Bild oder kurzes Beispiel der Ausgabe (wenn es etwas zu sehen gibt).
3. Schnellstart: Installieren und ein erstes Ergebnis in höchstens 3 Befehlen.
4. Funktionen: 3 bis 7 Punkte, je eine Zeile, Nutzen zuerst.
5. Benutzung: das häufigste Beispiel ausführlich, weitere verlinkt (docs/).
6. Konfiguration: nur wenn nötig, als Tabelle (Name, Standard, Bedeutung).
7. Mitmachen: ein Satz + Link auf CONTRIBUTING.md.
8. Lizenz: ein Satz + Link auf LICENSE.

## Nach Projektart anpassen
| Projektart        | Schwerpunkt                                              |
|-------------------|----------------------------------------------------------|
| App/Webseite      | Bild, was der Nutzer sieht, wie man es öffnet            |
| Bibliothek        | Installation, kleinstes Codebeispiel, Link zur API-Doku   |
| Kommandozeile     | Installation, 3 typische Aufrufe mit Ausgabe              |
| Vorlage/Starter   | Was ist drin (Baum), wie kopiert man es, erster Schritt   |

## Abzeichen (Badges)
Nur für Fakten, die es wirklich gibt (Lizenz, Build-Status, Version). Höchstens 4.
Keine Abzeichen für Dinge ohne Quelle.

## Häufige Fehler
- Installationsbefehle für den falschen Paketmanager.
- Abschnitt "Funktionen" als Werbetext ohne Inhalt.
- Veraltete Bilder und Befehle (beim Schreiben einmal ausprobieren).
- Lange Einleitung, Schnellstart erst ganz unten.
- Interne Projektdokumente (Plan, Übergabe) im README erklären.

## Prüffragen
- Kann ein Fremder nach dem Schnellstart etwas sehen oder benutzen?
- Steht nichts im README, was in docs/ besser aufgehoben ist?

# CONTRIBUTING schreiben

Ziel: Wer helfen will, weiss danach, wie er einen guten Beitrag macht, ohne nachzufragen.

## Abschnitte
1. Willkommen in einem Satz: Welche Beiträge sind erwünscht (Fehler melden, Code, Texte)?
2. Bevor du startest: Wo meldet man Fehler, wo stellt man Fragen? Erst suchen, dann melden.
3. Entwicklungsumgebung: Voraussetzungen (Version), Installieren, Starten, Testen.
   Befehle exakt aus AGENTS.md (Abschnitt Befehle) übernehmen.
4. Arbeitsablauf: Zweig anlegen, kleine Änderung, Tests, Beschreibung des Pull Requests.
5. Regeln für Code: Stil, Namen, Formatierer und Linter mit Befehl.
6. Commit-Nachrichten: Format mit Beispiel (passt zum Skill commit-message, falls vorhanden).
7. Prüfung: Wer prüft, wie lange dauert es ungefähr, was passiert bei Rückfragen.
8. Fehler melden: Vorlage (Was erwartet, was passiert, Schritte, Version, Bild).
9. Verhalten: ein Satz und Link, falls es einen Verhaltenskodex gibt.

## Vorlage Fehlermeldung (zum Einfügen)
```markdown
**Was passiert:** ...
**Was erwartet:** ...
**Schritte:** 1. ... 2. ...
**Version / System:** ...
```

## Häufige Fehler
- Regeln, die niemand prüft (dann weglassen).
- Befehle, die nur auf einem Betriebssystem laufen, ohne Hinweis.
- Kein Hinweis, wie gross ein Beitrag sein darf.

## Prüffragen
- Kann jemand ohne Vorwissen die Tests lokal grün laufen lassen?
- Ist klar, was einen Beitrag "fertig" macht?
